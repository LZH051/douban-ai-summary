# 开发问题与设计取舍记录

## 已确定的设计

### 为什么选择豆瓣电影 Top250

- 列表页字段比较集中，标题、评分、评价人数和简介可以在同一页面取得。
- 每页约25条，适合先用一页验证，再决定是否采集全部10页。
- 第一阶段不进入评论详情页，减少请求数量和触发访问限制的风险。

### 如何控制请求频率

- 首次开发只采集一页。
- 多页采集时，每页之间随机等待2～5秒。
- 遇到403、418或429立即停止，不自动高频重试。
- 不使用代理池、验证码绕过或其他规避访问限制的方式。

### 如何避免重复数据

- CSV清洗阶段按照 `douban_id` 去重。
- MySQL中对 `douban_id` 和 `source_url` 设置唯一约束。
- 入库使用 `INSERT IGNORE`，重复运行不会产生重复记录。

## 实际问题记录

### 问题 1：PowerShell 输出的中文标题看起来像乱码

- 报错或现象：第一次请求成功并解析出25条数据，但终端把标题显示为
  `è‚–ç”³å…‹...` 一类字符。
- 发生步骤：在 PowerShell 中直接查看程序输出和CSV内容时。
- 原因分析：进一步用 Python 按 `utf-8-sig` 读取CSV，并把标题转换成
  Unicode转义后，确认首条是“肖申克的救赎”。因此CSV文件内容没有损坏，
  实际问题是终端输出编码与文本编码不一致。
- 解决方法：网页响应仍明确使用UTF-8解码；CSV按 `utf-8-sig` 写入和读取，
  验证数据时使用Python读取，不以终端一次显示结果作为文件损坏的依据。
- 学到的内容：需要分别判断HTTP响应解码、CSV文件编码和终端显示编码，
  终端乱码不一定代表源数据或文件已经乱码。

### 问题 2：列表页短评字段可能不存在

- 报错或现象：当前页面没有取得旧版页面常见的 `span.inq` 短评，25条简介
  都会退化成“暂无简介”。
- 发生步骤：核对标题、评分、评价人数和简介四个字段时。
- 原因分析：网页结构和返回内容会变化，不能假定每条电影都存在短评节点。
- 解决方法：优先读取 `span.inq`；没有短评时，改用列表页中的导演、演员、
  年份、国家和类型等基本介绍；两者都不存在时才填“暂无简介”。
- 学到的内容：网页采集代码需要为可选字段设计明确的降级策略，并在运行后
  统计缺失情况。

### 问题 3：AI 摘要脚本缺少命令行付费确认保护

- 报错或现象：使用 `python src/ai_summary.py --help` 检查参数时，旧脚本
  没有解析命令行参数，而是直接进入默认的5条摘要生成流程。
- 发生步骤：准备执行已授权的5条 AI 摘要之前。
- 原因分析：付费确认保护只写在总入口 `main.py` 中，直接运行
  `ai_summary.py` 会绕过该保护，而且未识别的 `--help` 也不会生效。
- 解决方法：为 `ai_summary.py` 增加 `argparse`，支持 `--limit 5-10`，
  并强制要求 `--confirm-paid-run`；未确认时立即退出，不连接 AI 接口。
- 验证结果：本次数据库最终恰好保存5条摘要，没有超过用户授权数量；修改后
  `--help` 可以正常显示，并且不会触发新的 API 调用。
- 学到的内容：可能产生费用的功能需要在每一个可直接执行的入口上设置确认
  闸门，不能只依赖上层调用者。
