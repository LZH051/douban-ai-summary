# 开发问题与设计取舍记录

## 已确定的设计

### 为什么选择豆瓣电影 Top250

- 列表页字段比较集中，标题、评分、评价人数和简介可以在同一页面取得。
- 每页约25条，适合先用一页验证，再决定是否采集全部10页。
- 第一阶段不进入评论详情页，减少请求数量和触发访问限制的风险。


### 如何避免重复数据

- CSV清洗阶段按照 `douban_id` 去重。
- MySQL中对 `douban_id` 和 `source_url` 设置唯一约束。
- 入库使用 `INSERT IGNORE`，重复运行不会产生重复记录。

## 实际问题记录

### 问题 1：如何避免高频请求触发访问限制

- 报错或现象：豆瓣页面存在访问频率限制。如果短时间连续发送大量请求，可能返回403、418或429状态码，导致采集任务中断。

- 发生步骤：准备采集豆瓣电影 Top250 多页数据时。

- 原因分析：连续、高频的自动化请求会增加网站服务器压力，也容易被识别为异常访问。

- 解决方法：
  1. 开发阶段只采集一页，先验证字段解析是否正确；
  2. 每页最多采集约25条电影；
  3. 多页采集时，每次请求之间随机等待2～5秒；
  4. 遇到403、418或429时立即停止；
  5. 不进行连续自动重试，不使用代理池或验证码绕过。

### 问题 2：列表页短评字段可能不存在

- 报错或现象：当前页面没有取得旧版页面常见的 span.inq 短评，如果没有设计备用字段，25条电影的简介都会变成“暂无简介”。

- 发生步骤：检查标题、评分、评价人数和简介四个字段时。

- 原因分析：网页结构和返回内容可能发生变化，不能假设每部电影都存在短评节点。

- 解决方法：
  1. 优先读取 span.inq 中的电影短评；
  2. 没有短评时，改用列表页中的导演、演员、年份、国家和类型等基本介绍；
  3. 两种内容都不存在时，才填写“暂无简介”；
  4. 清洗完成后统计简介缺失和占位数量。

### 问题 3：重复运行可能产生重复电影
- 报错或现象：重复执行采集和入库脚本时，同一部电影可能被多次写入数据库，导致电影数量和统计结果不准确。

- 发生步骤：验证项目能否安全地重复运行时。

- 原因分析：如果只使用普通 INSERT，数据库不会自动判断电影是否已经存在。

- 解决方法：
  1. CSV 清洗阶段按照 douban_id 删除重复电影；
  2. SQLite 中为 douban_id 设置唯一约束；
  3. 为 source_url 设置唯一约束；
  4. 数据入库使用 INSERT OR IGNORE；
  5. AI 摘要表中的 movie_id 也设置唯一约束，避免一部电影保存多条重复摘要。
